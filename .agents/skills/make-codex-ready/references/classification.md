# Decision classification

- **CONFIRMED:** An explicit current instruction or recorded accepted decision.
- **WORKING PROPOSAL:** A desired direction, suggestion or mock-up detail that is not locked.
- **OPEN QUESTION:** An unresolved choice that could change implementation, policy or acceptance criteria.
- **HISTORICAL:** An earlier idea retained for context and traceability.
- **SUPERSEDED:** An earlier decision replaced by a newer confirmed decision.

## Evidence rules

- Visual designs prove that a concept was explored, not that every field, route, price or state is confirmed.
- Code and configuration prove implementation state, not automatically desired product intent.
- A planning conversation can confirm a decision when the user clearly accepts it; enthusiasm or lack of objection alone is insufficient.
- When sources conflict, apply the repository's documented hierarchy. If no hierarchy exists, surface the conflict and request resolution when it blocks safe work.
- Preserve superseded decisions for traceability and link them to their replacements.
