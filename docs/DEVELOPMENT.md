# Development

## Prerequisites

- Node.js 24.x
- pnpm 11.x
- A configured Supabase project
- Values from `.env.example` copied into a local `.env`

## Setup

```sh
pnpm install
pnpm dev
```

The application uses Vite and TanStack Start. The package workspace uses a
hoisted node linker and explicitly allows the `esbuild` package build.

## Commands

| Command | Purpose |
| --- | --- |
| `pnpm dev` | Start the development server |
| `pnpm build` | Create the production build |
| `pnpm build:dev` | Build using development mode |
| `pnpm preview` | Preview a production build |
| `pnpm lint` | Run ESLint across the repository |
| `pnpm format` | Apply Prettier formatting |

No automated test command currently exists.

## Source organization

- Put file-based routes in `src/routes/`.
- Put shared feature components in `src/components/`.
- Put reusable UI primitives in `src/components/ui/`.
- Put project tab implementations in `src/components/project-tabs/`.
- Put feature data operations and domain helpers in `src/lib/`.
- Put Supabase clients and middleware in `src/integrations/supabase/`.
- Put database changes in `supabase/migrations/`.

Read `src/routes/README.md` before adding or moving routes.

## Generated files

- `src/routeTree.gen.ts` is generated by the router tooling.
- `src/integrations/supabase/types.ts` is generated from the database schema.

Do not maintain either file manually. Regenerate them through their owning tool
after relevant source or schema changes.

## Environment handling

Public browser values and server values are listed in `.env.example`. Never put
real credentials in Markdown or source control. The service-role key is optional
and server-only.

## Change workflow

1. Check `git status` and inspect relevant existing diffs.
2. Read the closest documentation and source files.
3. Make the smallest coherent change without replacing unrelated working code.
4. Update documentation when behavior, schema, routes, or operations change.
5. Run `pnpm lint` for source or configuration changes.
6. Run `pnpm build` for compilation, routing, SSR, or production-bundle changes.
7. Manually verify affected auth, permission, mobile, and error states.
8. Report commands run, skipped checks, and remaining setup requirements.

## Manual verification priorities

Because the repository has no automated test suite, prioritize sign-in and
recovery, onboarding, role boundaries, invitations, cross-workspace isolation,
project assignment, photo access, small-screen layouts, and production builds.
